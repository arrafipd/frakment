**Frakment** is a component registry for React and React Native. Every component is our own primitive, with styling and motion built in. One file you can read, copy, and modify, on web and native alike.

## Why Frakment

Most component registries still pull in a dependency chain. Radix primitives for behavior, Motion or Framer Motion for animation, CVA for variants, a theming layer you wire up yourself. Copy-pasting the file does not free you from maintaining the ecosystem around it.

Frakment ships the whole stack in one file. The component is the primitive, the styling, and the motion. There is no `useButton()` to import, no `transition` class to add, no animation library to install.
Motion is per component, not a global system. An accordion expands at a different rate than a dialog enters, because the default is chosen for that component. You override it with a single prop, or edit the file for full control. There is no shared `easeInOut` token, no global duration map.

The same model applies on both platforms. Web uses CSS transitions with a per-component default. Native uses inline style with state today, and will adopt Reanimated for tweened motion. The API stays the same on both.
## Where Frakment is today

### Web

The web registry ships 48 components. `Button` is fully on the Frakment stack: our own primitive, our own motion, no external behavior library. The remaining 27 interactive primitives (accordion, dialog, dropdown, tabs, and so on) still use `radix-ui` for behavior and Motion v14 for animation. They work today and are documented. The migration is incremental.
### Native

The native registry ships 1 component: `Button`. The primitive is React Native's `Pressable`, styled with NativeWind and CVA. Pressed state is handled with `useState`, not a motion library yet. Motion on native is next.

The direction is zero external runtime dependencies on primitives and motion, on both platforms. `Button` establishes the pattern that the rest will follow: our own primitive, our own motion, one file.

## Principles

### One file, one export

Every component ships as a single source file, on web and native. No sidecar hook, no sidecar animation config, no sidecar theme file. The exports inside that file follow the same shape across the registry.

### No hidden dependency chain

Web components depend only on `class-variance-authority`, `lucide-react`, and, for components still on Radix, `radix-ui` plus `motion`. Native components depend on `class-variance-authority`, `lucide-react-native`, NativeWind, and React Native. When migration completes, both shrink to CVA plus the platform runtime.
### Motion is per component

Defaults are chosen per component, not from a global token set. There is no shared `easeInOut`, no shared `durationSlow`, no shared `springSoft`. The component knows its own motion, on whatever platform it runs.

### Accessible by default

Web components handle keyboard navigation, focus management, and `aria` wiring. Native components handle `accessibilityRole`, `accessibilityState`, and touch target sizing. Both meet WCAG 2.1 AA on the component itself.

### Copy-paste first, npm optional

The primary distribution is copy-paste. The CLI automates it for web. Native is manual copy from the docs for now. npm packages are optional on both and secondary.

### AI-native

The registry publishes `llms.txt`, an MCP server, and Skills so agents can read the source directly, install components, and reason about composition. Docs are the source on both platforms.

## Motion model

Motion is a first-class layer, not an add-on. Components that animate ship with a default tuned for their behavior. An accordion expands at one rate, a dialog enters at another. The default is opinionated. You should not have to configure it to get something that feels right.

### Web

Web motion is CSS. Override the default through a single prop.
```tsx title="example.tsx"
<Button motion="300ms cubic-bezier(0.32, 0.72, 0, 1)">Save</Button>;
<Button motion="200ms ease-out">Save</Button>;
<Button motion="off">Save</Button>;
```

`motion` accepts CSS transition shorthand: a duration (`200ms`, `0.4s`), optionally followed by an easing (`ease-out`, `cubic-bezier(...)`). `off` disables motion for that instance.

`prefers-reduced-motion` wins unconditionally. If the user has it on, motion is disabled regardless of what the prop says. This is not configurable.

### Native

Native motion is in progress. Current native `Button` uses instant state changes on press, no tweened animation. The plan is to adopt Reanimated 4 with the same per-component default model. When that lands, motion will be resolved inside the component from its own default.
## Distribution

Frakment components distribute three ways on web. Native is manual for now.

### Web

- CLI: `npx frakment add button` copies the component into `components/ui/`, resolves `registryDependencies`, and verifies the file hash.
- Manual: copy from the source tab on any component page. The code shown is the file you get.
- npm: install `@frakment/<component>` (optional, in progress). Useful if you want pinned versions.

### Native

Copy the source from the docs. The CLI does not install native components yet. A native CLI flag is on the roadmap.

Under the hood, the registry is a flat directory of JSON manifests (`public/r/*.json`). Each manifest includes the component source, its npm dependencies, and its `registryDependencies`. The CLI reads these. So does the docs site. So does the MCP server.

`--dry-run` prints what the CLI would do without writing. `--skip-dependencies` installs only the component, no registry dependencies.

## AI-native

Frakment publishes three things specifically for agents.

- `llms.txt` describes every component, its install command, and its props.
- MCP server (`@frakment/mcp`) lets Claude, Cursor, and other MCP clients query the registry, install components, and read source without leaving the chat.
- Skills (`public/skills/frakment-usage/SKILL.md`) teaches an agent the registry's conventions: how to install, how to compose, what not to do.

The docs are also the source. The code block on every component page is the actual file you would copy.
