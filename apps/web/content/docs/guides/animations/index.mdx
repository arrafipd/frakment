---
title: Animations
description: Configure CSS transitions on Frakment web components.
---

Frakment web components that expose a `motion` prop use CSS transitions.

The prop changes the transition for that component without requiring an animation library import.

## Configure a transition

The `motion` prop accepts a duration followed by an optional CSS easing value.

```tsx
<Accordion motion="150ms ease-out" collapsible type="single">
  <AccordionItem value="a">
    <AccordionTrigger>Shipping options</AccordionTrigger>
    <AccordionContent>Choose a delivery method.</AccordionContent>
  </AccordionItem>
</Accordion>
```

You can set a duration in milliseconds or seconds, use a CSS easing value, or pass `off` to disable the transition.

| Value | Meaning |
| :-- | :-- |
| `150` or `300ms` | Transition duration in milliseconds. |
| `0.3s` | Transition duration in seconds. |
| `ease-in-out` | CSS easing value. |
| `cubic-bezier(0.4, 0, 0.2, 1)` | Custom CSS easing value. |
| `off` | Disable the transition. |

Components may provide their own default transition and may expose the prop on different parts.

Check the API section of the component page before overriding its transition.

## Reduced motion

Frakment web components respect the `prefers-reduced-motion` system preference.

When reduced motion is enabled, component transitions are disabled.

## Native components

Native components use immediate state changes and do not expose the web `motion` prop.

## Custom animations

Use CSS animations for custom effects, and disable them when reduced motion is preferred.

```css
.fade-in {
  animation: fade-in 200ms ease-out both;
}

@keyframes fade-in {
  from {
    opacity: 0;
    transform: translateY(8px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

@media (prefers-reduced-motion: reduce) {
  .fade-in {
    animation: none;
  }
}
```

See the [component catalog](/docs/components) for component-specific APIs.
