### Popover

<ComponentPreview name="popover" title="popover.tsx">
  <PopoverDemo />
</ComponentPreview>

**Popover** renders a floating panel anchored to a trigger. Position is resolved with Floating UI, so the panel flips and shifts automatically when it would overflow the viewport. Opens on trigger click, closes on outside click or `Escape`. Non-modal: focus returns to the trigger, no focus trap. `PopoverHeader`, `PopoverTitle`, and `PopoverDescription` wire `aria-labelledby` and `aria-describedby` for you.

</Steps>

```tsx

  <PopoverContent>Content</PopoverContent>
</Popover>
```

See the [Popover docs](/docs/components/popover) for the full API reference.

### Button `as` prop

Button accepts `as` to render a different root element or component. Pass `as={Link}` for router links, `as={CustomComponent}` for a wrapped surface, or omit to keep the default `<button>` / `<a>` behavior based on `href`.

```tsx
import Link from "next/link";
import { Button } from "@/components/ui/button";

<Button as={Link} href="/pricing" variant="outline">Pricing</Button>
```

No API breaking changes. `href` and `onClick` continue to work as before. See the [Button docs](/docs/components/button) for the updated router link guidance.

### Separator

Separator no longer depends on `radix-ui`. It renders as a `div` with `role="none"` by default, or `role="separator"` with `aria-orientation` when `decorative={false}`.

**Changed:**

- Removed `radix-ui` from `dependencies`. No npm install needed.
- `decorative` prop now controls `role` directly.

No API breaking changes. See the [Separator docs](/docs/components/separator).

### Select

<ComponentPreview name="select" title="select.tsx">
  <SelectDemo />
</ComponentPreview>

**Select** no longer depends on `radix-ui`. The listbox runs on Floating UI with two placement modes: `item-aligned` (default, overlaps the selected item with the trigger) and `popper` (anchors below the trigger). Keyboard navigation, type-ahead, and form submission follow the native select contract.

**Changed:**

- Removed `radix-ui` from `dependencies`. Added `@floating-ui/react-dom`.
- New `position` prop on `SelectContent`: `item-aligned` (default) or `popper`.
- Controlled `open` and `value` now honor the prop instead of the initial state.
- New `SelectScrollUpButton` and `SelectScrollDownButton` for long lists.
- Scroll inside the listbox is locked; the page beneath does not scroll while open.

No API breaking changes. See the [Select docs](/docs/components/web/select).

### Badge

<ComponentPreview name="badge" title="badge.tsx">
  <BadgeDemo />
</ComponentPreview>

**Badge** no longer depends on `radix-ui`. The surface height drops from `h-6` to `h-5` to match the shadcn/ui baseline, and the primitive gains an `as` prop and an `iconOnly` mode.

**Changed:**

- Removed `radix-ui` from `dependencies`.
- New `registryDependency`: `slot`.
- Height `h-6` → `h-5`, horizontal padding `px-2.5` → `px-2`, icon size `size-3.5` → `size-3`.
- New `as` prop for router links and custom components. `asChild` stays for backward compatibility.
- New `iconOnly` prop renders a square badge with no horizontal padding. Use when the badge wraps only an icon.
- Spinner inside a badge now renders at `size-2.5` with a 1px ring.

See the [Badge docs](/docs/components/web/badge).

### Avatar

<ComponentPreview name="avatar" title="avatar.tsx">
  <AvatarDemo />
</ComponentPreview>

**Avatar** no longer depends on `radix-ui`. The image loading state lives in a small context hook, so `AvatarImage` and `AvatarFallback` share it. A failed load auto-styles the fallback with the destructive token — distinguishable from a missing image without extra state.

**Changed:**

- Removed `radix-ui` from `dependencies`.
- New `data-status` attribute on `AvatarFallback`: `idle`, `loading`, `loaded`, `error`.
- Failed `AvatarImage` loads auto-render the fallback with `bg-destructive` and `text-white`.
- `--destructive` in light mode drops chroma from `0.245` to `0.18` for a softer surface across Button, Badge, and Input.

See the [Avatar docs](/docs/components/web/avatar).

### Collapsible

<ComponentPreview name="collapsible" title="collapsible.tsx">
  <CollapsibleDemo />
</ComponentPreview>

**Collapsible** no longer depends on `radix-ui` or `motion/react`. The reveal runs through Frakment's motion engine, and the height animates via CSS grid rows.

**Changed:**

- Removed `radix-ui` and `motion` from `dependencies`.
- New `motion` prop accepts `"off"`, `"150"`, `"150 ease-out"`, or `"150 cubic-bezier(...)"`. Default is a 450ms smooth-out curve.
- Per-content override on `CollapsibleContent`.
- Height animates via CSS grid rows (`0fr` to `1fr`).
- `CollapsibleTrigger` accepts `as` for custom trigger elements. `asChild` stays for backward compatibility.

See the [Collapsible docs](/docs/components/web/collapsible).

### `as` prop rollout (Badge, Collapsible, Button Group Text)

**Badge**, **Collapsible Trigger**, and **Button Group Text** now accept a single polymorphic `as` prop instead of `asChild`. Pass `as={Link}` to render a router link, `as={Button}` to slot a custom surface, or omit to keep the default element.

**Changed:**

- `Badge` accepts `as`. `asChild` is removed; use `as={Link}` for anchors or `as={Custom}` for other elements.
- `CollapsibleTrigger` accepts `as`. `asChild` is removed.
- `ButtonGroupText` accepts `as`. `asChild` is deprecated and kept for backward compatibility.

See the [Badge](/docs/components/web/badge), [Collapsible](/docs/components/web/collapsible), and [Button Group](/docs/components/web/button-group) docs.

### Input OTP

<ComponentPreview name="input-otp" title="input-otp.tsx">
  <InputOTPDemo />
</ComponentPreview>

**Input OTP** no longer depends on `input-otp`. The field renders a real hidden `<input>` so paste, backspace, arrow navigation, and form submission work natively. Each slot is a styled sibling driven by the input value.

**Changed:**

- Removed `input-otp` from `dependencies`.
- Exports `digits`, `chars`, and `alphanumeric` regex patterns instead of `REGEXP_*` constants.
- Pattern filtering runs on `onChange` so pasted values are sanitized against the pattern.

See the [Input OTP docs](/docs/components/input-otp).

### Native Separator & Button Group

<ComponentPreview name="native/separator" src="../../apps/native/registry/separator.tsx" title="separator.tsx">

<ComponentPreview name="native/button-group" src="../../apps/native/registry/button-group.tsx" title="button-group.tsx">

**Separator** and **Button Group** are now available for React Native via Expo. Separator renders as a `View` with a 1px line. Button Group lays out children in a row or column, strips the inner border and radius on adjacent children, and paints the separator variant with the `input` token so it matches the web composition.

Both read colors from `useThemeColors()`, so light and dark mode track the device system preference.
