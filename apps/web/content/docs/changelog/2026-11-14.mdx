This release adds **Popover**, migrates **Select** and **Separator** off `radix-ui`, ships first-party **Button Group**, and adds an `as` prop to **Button** for router links and custom components.

- [Popover](#popover): Floating panel anchored to a trigger.
- [Select](#select): Floating UI listbox with item-aligned and popper modes.
- [Button `as` prop](#button-as-prop): Render router links and custom components.
- [Separator](#separator): No more `radix-ui`.
- [Button Group](#button-group): Own primitive replaces the Radix Slot.
- [Native Separator & Button Group](#native-separator--button-group): Native ports.

### Popover

<ComponentPreview name="popover" title="popover.tsx">
  <PopoverDemo />
</ComponentPreview>

**Popover** renders a floating panel anchored to a trigger. Position is resolved with Floating UI, so the panel flips and shifts automatically when it would overflow the viewport. Opens on trigger click, closes on outside click or `Escape`. Non-modal: focus returns to the trigger, no focus trap. `PopoverHeader`, `PopoverTitle`, and `PopoverDescription` wire `aria-labelledby` and `aria-describedby` for you.

### Button `as` prop

Button accepts `as` to render a different root element or component. Pass `as={Link}` for router links, `as={CustomComponent}` for a wrapped surface, or omit to keep the default `<button>` / `<a>` behavior based on `href`.

```tsx
import Link from "next/link";
import { Button } from "@/components/ui/button";

<Button as={Link} href="/pricing" variant="outline">Pricing</Button>
```

No API breaking changes. `href` and `onClick` continue to work as before. See the [Button docs](/docs/components/button) for the updated router link guidance.

### Separator

Separator no longer depends on `radix-ui`. It renders as a `div` with `role="none"` by default, or `role="separator"` with `aria-orientation` when `decorative={false}`.

**Changed:**

- Removed `radix-ui` from `dependencies`. No npm install needed.
- `decorative` prop now controls `role` directly.

No API breaking changes. See the [Separator docs](/docs/components/separator).

### Button Group

Button Group now uses Frakment's own Slot primitive instead of the Radix Slot. All ten compositions (dropdown, input, input group, nested, select, separator, split, size, orientation, demo) continue to work without changes.

**Changed:**

- Removed `radix-ui` from `dependencies`.
- New `registryDependency`: `slot`.

See the [Button Group docs](/docs/components/button-group).

### Select

<ComponentPreview name="select" title="select.tsx">
  <SelectDemo />
</ComponentPreview>

**Select** no longer depends on `radix-ui`. The listbox runs on Floating UI with two placement modes: `item-aligned` (default, overlaps the selected item with the trigger) and `popper` (anchors below the trigger). Keyboard navigation, type-ahead, and form submission follow the native select contract.

**Changed:**

- Removed `radix-ui` from `dependencies`. Added `@floating-ui/react-dom`.
- New `position` prop on `SelectContent`: `item-aligned` (default) or `popper`.
- Controlled `open` and `value` now honor the prop instead of the initial state.
- New `SelectScrollUpButton` and `SelectScrollDownButton` for long lists.
- Scroll inside the listbox is locked; the page beneath does not scroll while open.

No API breaking changes. See the [Select docs](/docs/components/web/select).

### Native Separator & Button Group

**Separator** and **Button Group** are now available for React Native via Expo. Separator renders as a `View` with a 1px line. Button Group lays out children in a row or column, strips the inner border and radius on adjacent children, and paints the separator variant with the `input` token so it matches the web composition.

Both read colors from `useThemeColors()`, so light and dark mode track the device system preference.
