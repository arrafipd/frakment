Test Results renders a test run as a nested trace. The header shows the total count and failure summary, each suite collapses into its tests, and failing tests expand into the assertion output.

Test Results is a **composition**, not a primitive. It composes [Trace](/docs/components/trace) and [Code Block](/docs/components/code-block).

            <TraceLine />
          </Trace>
        </TraceCollapsibleContent>
      </TraceCollapsible>
    </Trace>
  </TraceCollapsibleContent>
</TraceCollapsible>
~~~

- **TraceCollapsible (top)** — the run, header shows total count and failure summary
- **TraceCollapsible (per suite)** — one per test file, header shows suite name and its own counts
- **TraceLine (per test)** — a single test, marked `error` when failed
- **Code Block** — the failure output, collapsible under the failed test

## Counts

Both the run header and each suite header render a count string: total tests, failures, skips. Compute the run counts by flattening all suites.

~~~ts title="test-results.ts"
function countTests(tests: Test[]) {
  return {
    total: tests.length,
    failed: tests.filter((test) => test.status === "failed").length,
    skipped: tests.filter((test) => test.status === "skipped").length,
  }
}
~~~

## Accessibility

- Each test row is text. Status is conveyed by the icon and by the `error` color.
- Failed tests auto-expand their assertion output. Screen readers announce the open state via the trigger.
- The suite header carries the counts, so a collapsed suite still announces its status.
- `prefers-reduced-motion` disables collapse animation.

## Best Practices

- **Group by file.** A suite is a test file, not a category.
- **Open failing suites by default.** Passing suites can stay collapsed.
- **Show the raw failure output.** Do not rewrite the assertion message.
- **Pair with a plain-text summary.** The results are evidence, not the answer.
