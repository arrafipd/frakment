Frakment provides MCP tools to search the web registry, inspect component source, compose scenarios, and retrieve CLI install commands.

The MCP server does not write files into a project or execute the returned commands.

The MCP server exposes web components only; use `/r/expo/index.json` and the CLI `--expo` option for native components.

Connect from any AI client that supports MCP over stdio.

For clients without MCP support, the registry HTTPS endpoints and provider-neutral skill offer alternative workflows.

The CLI and MCP server require Node.js 22.18.0 or newer.

## Tools

### list_components

Returns every web component with `name` and `description`.

**Input**: none

**Output**: text list of components.

### view_component

Returns the component files, npm dependencies, and registry dependencies.

Binary assets remain base64 text and are labeled with their encoding in the file header.

<PropsTable
  rows={[
    {
      name: "name",
      type: "string",
      description: "      Web component slug from /r/index.json.",
      required: true,
    },
  ]}
/>

**Output**: markdown with file contents, npm dependencies, and registry dependencies. Binary assets include an encoding label and retain their base64 content.

### search_components

Case-insensitive substring search across web component `name` and `description`.

<PropsTable
  rows={[
    {
      name: "query",
      type: "string",
      description: "Free-text search term.",
      required: true,
    },
  ]}
/>

**Output**: matching components with descriptions.

### get_install_command

Formats the CLI command without validating the component name. Call `list_components` first to choose a valid slug.

<PropsTable
  rows={[
    {
      name: "name",
      type: "string",
      description: "      Web component slug.",
      required: true,
    },
  ]}
/>

**Output**: `npx frakment@latest add <name>`

### list_scenarios

Returns the built-in compositions available for common UI scenarios. No parameters.

**Output**: a list of scenario names with one-line descriptions.

### compose

Returns the curated components, install command, and a note about registry dependencies for a scenario.

<PropsTable
  rows={[
    {
      name: "scenario",
      type: "string",
      description: "Scenario key from `list_scenarios`.",
      required: true,
    },
  ]}
/>

**Output**: scenario name, description, components, install command, and dependency note; the CLI resolves registry dependencies.

Supported scenarios: `chat`, `agent-timeline`, `code-output`, `login-form`, `settings-panel`, `empty-state`, `search-input`.

## Client configuration

<Callout type="info" title="stdio transport">
  Frakment MCP speaks stdio. Launch it from any MCP client that spawns
  subprocesses.
</Callout>

### Claude Desktop

Config lives at `~/Library/Application Support/Claude/claude_desktop_config.json` on macOS, or `%APPDATA%\Claude\claude_desktop_config.json` on Windows.

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "frakment": {
      "command": "npx",
      "args": ["-y", "@frakment/mcp"]
    }
  }
}
```

### VS Code with GitHub Copilot

Save this configuration as `.vscode/mcp.json`:

```json title="mcp.json"
{
  "servers": {
    "frakment": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@frakment/mcp"]
    }
  }
}
```

### Cursor

Config lives at `~/.cursor/mcp.json`:

```json title="mcp.json"
{
  "mcpServers": {
    "frakment": {
      "command": "npx",
      "args": ["-y", "@frakment/mcp"]
    }
  }
}
```

### Generic stdio

Any client that spawns stdio processes:

```bash
npx -y @frakment/mcp
```

## Troubleshooting

<Accordion type="single" collapsible>

<AccordionItem value="404">
  <AccordionTrigger>Tool returns HTTP 404</AccordionTrigger>
  <AccordionContent>
    The component name does not exist in the registry. Call `list_components`
    first to get a valid slug.
  </AccordionContent>

<AccordionItem value="fetch-failed">
  <AccordionTrigger>fetch failed</AccordionTrigger>

  </AccordionContent>
