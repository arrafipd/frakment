A login form is a sign-in layout assembled from Frakment's [button](/docs/components/button), [card](/docs/components/card), [field](/docs/components/field), and [input](/docs/components/input) primitives.

This composition includes a basic layout, a social sign-in layout, and a branded layout.

It is not a standalone registry item, and its forms do not implement authentication or application-specific validation.

## Usage

Use the primitives to build the layout, then connect form submission to your application's authentication flow.

```tsx title="login-form.tsx"
import { Button } from "@/components/ui/button";
import {
  Card,
  CardContent,
  CardHeader,
  CardTitle,
} from "@/components/ui/card";
import { Field, FieldGroup, FieldLabel } from "@/components/ui/field";
import { Input } from "@/components/ui/input";

export function LoginForm() {
  return (
    <Card>
      <CardHeader>
        <CardTitle>Login to your account</CardTitle>
      </CardHeader>
      <CardContent>
        <form>
          <FieldGroup>
            <Field>
              <FieldLabel htmlFor="email">Email</FieldLabel>
              <Input id="email" type="email" autoComplete="email" required />
            </Field>
            <Field>
              <FieldLabel htmlFor="password">Password</FieldLabel>
              <Input id="password" type="password" autoComplete="current-password" required />
            </Field>
            <Field>
              <Button type="submit">Login</Button>
            </Field>
          </FieldGroup>
        </form>
      </CardContent>
    </Card>
  );
}
```

## Anatomy

The basic layout places the form inside a card and groups its labelled controls with `FieldGroup`.

```text
Card
├── CardHeader
└── CardContent
    └── form
        └── FieldGroup
            ├── Field (email)
            ├── Field (password)
            └── Field (submit action)
```

The social layout adds social sign-in buttons and a `FieldSeparator`, while the branded layout places its brand mark and actions in a standalone form surface.

## Accessibility

- Give each input a matching `FieldLabel` and `id`, and set the appropriate autocomplete value for email and password fields.
- For invalid fields, set `data-invalid` on `Field`, set `aria-invalid` on the control, and render `FieldError` for the validation message.
- Connect submit and social sign-in buttons to real authentication handlers before using the layouts in an application.

## Best Practices

- **Treat the examples as layout starting points.** Add the validation and authentication behavior required by your application.
- **Replace placeholder links.** Account, recovery, and legal links in the examples use `href="#"`.
- **Keep the primary action clear.** Use one primary submit button for the form.
