A signup form combines Frakment's [button](/docs/components/button), [card](/docs/components/card), [field](/docs/components/field), and [input](/docs/components/input) primitives into account creation layouts.

The examples include a basic form, a two-column password layout, and a branded form with social sign-in actions.

These are copyable layouts, not a standalone registry item, and they do not implement authentication or application-specific validation.

## Usage

Use the primitives to build the form and connect submission to your account creation flow.

```tsx title="signup-form.tsx"
import { Button } from "@/components/ui/button";
import {
  Card,
  CardContent,
  CardHeader,
  CardTitle,
} from "@/components/ui/card";
import { Field, FieldGroup, FieldLabel } from "@/components/ui/field";
import { Input } from "@/components/ui/input";

export function SignupForm() {
  return (
    <Card>
      <CardHeader>
        <CardTitle>Create an account</CardTitle>
      </CardHeader>
      <CardContent>
        <form>
          <FieldGroup>
            <Field>
              <FieldLabel htmlFor="name">Full Name</FieldLabel>
              <Input id="name" type="text" autoComplete="name" required />
            </Field>
            <Field>
              <FieldLabel htmlFor="email">Email</FieldLabel>
              <Input id="email" type="email" autoComplete="email" required />
            </Field>
            <Field>
              <FieldLabel htmlFor="password">Password</FieldLabel>
              <Input
                id="password"
                type="password"
                autoComplete="new-password"
                required
              />
            </Field>
            <Field>
              <Button type="submit">Create Account</Button>
            </Field>
          </FieldGroup>
        </form>
      </CardContent>
    </Card>
  );
}
```

## Anatomy

The basic layout groups account fields and the submit action inside a card.

```text
Card
├── CardHeader
└── CardContent
    └── form
        └── FieldGroup
            ├── Field (name)
            ├── Field (email)
            ├── Field (password)
            └── Field (submit action)
```

The social layout adds a two-column password group, while the branded layout adds a brand mark, social actions, and terms text.

## API

`SignupFormBasic` accepts and forwards `React.ComponentProps<typeof Card>`.

`SignupFormSocial` and `SignupFormBranded` accept and forward `React.ComponentProps<"div">`.

`className` is merged with the default layout classes in all three examples.

## Accessibility

- Give every input a matching `FieldLabel` and `id`, and use the appropriate autocomplete value for each field.
- For invalid fields, set `data-invalid` on `Field`, set `aria-invalid` on the control, and render `FieldError` for the validation message.
- Connect form submission and social sign-in buttons to real authentication handlers before using the layouts in an application.

## Best Practices

- **Use the examples as layout starting points.** Add the validation and account creation behavior required by your application.
- **Replace placeholder links.** Sign-in, Terms of Service, and Privacy Policy links in the examples use `href="#"`.
- **Keep the primary action clear.** Use one primary submit button for the form.
