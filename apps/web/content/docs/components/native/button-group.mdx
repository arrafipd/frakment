A `View` wrapper that lays out children in a row (`horizontal`, default) or a column (`vertical`). Each direct child is cloned to strip the shared border and radius on the inner edges, so adjacent buttons read as a single unit. Outer corners keep their full radius.

## Usage

```tsx title="button-group.tsx"
import { Button } from "@/components/ui/button";
import { ButtonGroup } from "@/components/ui/button-group";
```

```tsx title="button-group.tsx"
<ButtonGroup>
  <Button variant="outline">Archive</Button>
  <Button variant="outline">Report</Button>
</ButtonGroup>
```

## Orientation

<ComponentPreview name="native/button-group-orientation" title="button-group-orientation.tsx" src="../../apps/native/examples/button-group-orientation.tsx">

Pass `orientation="vertical"`. Children stack in a column. Inner edges lose their border and radius the same way they do in a horizontal group, so the column reads as a single unit.

## Size

<ComponentPreview name="native/button-group-size" title="button-group-size.tsx" src="../../apps/native/examples/button-group-size.tsx">
  <NativeButtonGroupSize />
</ComponentPreview>

Buttons keep their own `size`. The group does not enforce size, so mixing `sm`, `default`, and `lg` inside the same group is allowed.

## Separator

<ComponentPreview name="native/button-group-separator" title="button-group-separator.tsx" src="../../apps/native/examples/button-group-separator.tsx">
  <NativeButtonGroupSeparator />
</ComponentPreview>

`ButtonGroupSeparator` wraps `Separator` with `alignSelf: "stretch"`, so it fills the group height without additional style. Use it when the visual separation between adjacent actions matters more than the tight border merge.

## Button Group Text

<ComponentPreview name="native/button-group-text" title="button-group-text.tsx" src="../../apps/native/examples/button-group-text.tsx">

`ButtonGroupText` renders a bordered surface for a label or an icon. String children are wrapped in a `Text` with the group foreground color. Non-string children render as-is.

## Accessibility

- Each child button keeps its own `accessibilityRole="button"` and `accessibilityState`. The group does not override them.
- Icon-only children should set `accessibilityLabel`. The group does not synthesize one.
- Visual size equals tap area. Groups of `xs` and `sm` buttons fall below the 44dp iOS minimum. Prefer `default` or `lg` for touch-critical actions.

## Best Practices

- **Group actions that belong to the same task.** Archive and Report belong together. Archive and Delete do not.
- **Keep group size uniform.** Mixing `sm` and `lg` inside a group reads as a bug, not a feature.
- **Use `ButtonGroupSeparator` sparingly.** The default border merge is enough for most cases.
- **Nested groups need the outer `ButtonGroup`.** The outer wrapper adds the gap between inner groups and keeps the composition readable.

## Platform notes

- **Border merge is inline.** Native does not have CSS child selectors. `ButtonGroup` clones its direct children and sets `borderRadius` and `borderWidth` on the inner edges. This works for `Button`, `ButtonGroupText`, and any child that accepts a `style` prop.
- **Dropdown, Input, Input Group, and Select demos are web-only for now.** The web Button Group page shows those compositions. Native ports are pending. The `ButtonGroup` API is identical and works with any child that renders a tappable surface.
- **The hero example uses three nested groups.** The web hero includes a dropdown trigger inside the third group. Native renders a plain button there because DropdownMenu is not ported yet. The nesting and group composition are otherwise identical.
