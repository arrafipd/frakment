Tabs organize related content into panels that switch in place. Only one panel is visible at a time, keeping dense interfaces compact.

## Usage

~~~tsx title="tabs.tsx"
import {
  Tabs,
  TabsContent,
  TabsList,
  TabsTrigger,
} from "@/components/ui/tabs";
~~~

~~~tsx title="tabs.tsx"
<Tabs defaultValue="account">
  <TabsList>
    <TabsTrigger value="account">Account</TabsTrigger>
    <TabsTrigger value="password">Password</TabsTrigger>
  </TabsList>
  <TabsContent value="account">Account settings.</TabsContent>
  <TabsContent value="password">Password settings.</TabsContent>
</Tabs>
~~~

### TabsList

Accepts native `div` props and forwards them to the tab list. The active trigger is marked with `aria-selected` and `data-state="active"`.

## As Prop

`TabsContent` accepts `as` to render a custom element. `TabsTrigger` renders a native `<button>` by default.

## Controlled

```tsx
const [value, setValue] = React.useState("tab-1")
<Tabs value={value} onValueChange={setValue}>{/* ... */}</Tabs>
```

## Keyboard

| Key | Action |
| :-- | :-- |
| `←` / `→` | Move between triggers (horizontal) |
| `↑` / `↓` | Move between triggers (vertical) |
| `Home` / `End` | First / last trigger |
| `Enter` / `Space` | Activate focused trigger |

## Data Attributes

| Attribute | Values |
| :-- | :-- |
| `data-slot` | `tabs`, `tabs-list`, `tabs-trigger`, `tabs-content` |
| `data-state` | `active` \| `inactive` |
| `data-orientation` | `horizontal` \| `vertical` |

## Accessibility

- Follows the WAI-ARIA tabs pattern.
- Triggers expose `role="tab"` and `aria-selected`.
- Keyboard: `ArrowLeft` and `ArrowRight` move between triggers.

## Best Practices

- **Keep tabs to three or four.** More tabs become a nav, not a tab list.
- **Pick a default.** Empty tab groups confuse users about the current state.
- **Do not nest tabs.** Nested tabs lose context; use a segmented control instead.
- **Do not lazy-load the first tab.** The default tab should not flash.
