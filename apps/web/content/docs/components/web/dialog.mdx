## Usage

~~~tsx title="dialog.tsx"
import {
  Dialog, DialogClose, DialogContent, DialogDescription,
  DialogFooter, DialogHeader, DialogTitle, DialogTrigger,
} from "@/components/ui/dialog";
~~~

~~~tsx
<Dialog>
  <DialogTrigger as={Button}>Open</DialogTrigger>
  <DialogContent>
    <DialogHeader>
      <DialogTitle>Title</DialogTitle>
      <DialogDescription>Description</DialogDescription>
    </DialogHeader>
    <DialogFooter>
      <DialogClose as={Button} variant="outline">Cancel</DialogClose>
      <Button>Save</Button>
    </DialogFooter>
  </DialogContent>
</Dialog>
~~~

## Data Attributes

| Attribute | Values | Applies to |
| :-- | :-- | :-- |
| `data-slot` | `dialog-trigger`, `dialog-content`, `dialog-header`, `dialog-footer`, `dialog-title`, `dialog-description`, `dialog-close` | Per sub-component |
| `data-state` | `open` \| `closed` | `Dialog`, `DialogContent`, `DialogOverlay` |

Use these in CSS or tests to target the current state:

```tsx
<DialogContent className="data-[state=open]:opacity-100 data-[state=closed]:opacity-0" />
```

## Keyboard

| Key | Action |
| :-- | :-- |
| `Esc` | Close the dialog |
| `Tab` | Move focus forward |
| `Shift + Tab` | Move focus backwards |
| `Enter` / `Space` | Activate focused element |

Focus is trapped inside `DialogContent` while open. On close, focus returns to the trigger.

## Controlled

Without `open`, the dialog manages its own state. Pass `open` and `onOpenChange` to control it:

```tsx
const [open, setOpen] = React.useState(false)

<Dialog open={open} onOpenChange={setOpen}>
  <DialogTrigger as={Button}>Open</DialogTrigger>
  <DialogContent>{/* ... */}</DialogContent>
</Dialog>
```

Use `defaultOpen` for an uncontrolled dialog that starts open.

## As Prop

`DialogTrigger` and `DialogClose` accept an `as` prop to render a custom element:

```tsx
<DialogTrigger as={Button} variant="outline">Settings</DialogTrigger>
```

Without `as`, the trigger renders as a native `<button>`.

## Motion

`DialogContent` accepts a `motion` prop to customize the entrance and exit timing:

```tsx
<DialogContent motion="200 ease-out">{/* ... */}</DialogContent>
```

The default is `150ms ease-out`. `motion="off"` disables the animation. `prefers-reduced-motion` is always respected.

## Accessibility

- Focus is trapped inside the dialog while open.
- `DialogTitle` and `DialogDescription` are announced to screen readers via `aria-labelledby` and `aria-describedby`.
- `Escape` closes the dialog.
- Clicking the backdrop closes the dialog.
- `role="dialog"` and `aria-modal="true"` are set on `DialogContent`.

## Best Practices

- **Do not use a dialog for navigation.** Use a sheet or a new route instead.
- **Keep content short.** If it needs to scroll, it might belong on its own page.
- **Provide multiple exits.** Cancel in the footer, Escape key, and outside click.
- **Put the destructive action last.** Primary on the right, destructive on the far right.
