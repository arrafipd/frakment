Message ships every primitive a chat UI needs. Layout primitives (`Message`, `MessageGroup`) handle alignment and avatar placement. `Bubble` provides the rounded visual box with variant colors. `MessageScroller` anchors the viewport, follows streamed replies, and restores position on refresh. `MessageAnimated` fades in an incoming local message with one line.

## Anatomy

```tsx
<MessageScrollerProvider>
  <MessageScroller>
    <MessageScrollerViewport>
      <MessageScrollerContent>
        <MessageScrollerItem messageId="1">
          <Message align="start">
            <MessageAvatar />
            <MessageContent>
              <MessageHeader />
              <Bubble>
                <BubbleContent />
                <BubbleReactions />
              </Bubble>
              <MessageFooter />
            </MessageContent>
          </Message>
        </MessageScrollerItem>
      </MessageScrollerContent>
    </MessageScrollerViewport>
    <MessageScrollerButton direction="end" />
  </MessageScroller>
</MessageScrollerProvider>
```

**Scroll container**

- **MessageScrollerProvider** - owns scroll state, item registry, visibility, and reduced-motion awareness
- **MessageScroller** - relative container with `overflow-hidden`
- **MessageScrollerViewport** - scrollable area; pass `preserveScrollOnPrepend` to keep position when prepending
- **MessageScrollerContent** - content wrapper that expands as messages arrive
- **MessageScrollerItem** - one message; pass `messageId` for anchors and `scrollAnchor` for turn anchoring
- **MessageScrollerButton** - scroll-to-end/start button; `direction="end"` (default) or `"start"`

**Message layout**

- **MessageGroup** - vertical stack of messages
- **Message** - one row; `align="start" | "end"` for side
- **MessageAvatar** - avatar slot; auto-positions when a footer is present
- **MessageContent** - content column between avatar and bubble
- **MessageHeader** - small text above the bubble (name, timestamp)
- **MessageFooter** - small text below the bubble (actions, timestamp)

**Bubble**

- **BubbleGroup** - vertical stack of bubbles inside a Message
- **Bubble** - rounded visual box; `variant` + `align`
- **BubbleContent** - inner text box; accepts `as` for anchor or router link
- **BubbleReactions** - absolute-positioned reaction strip; `align="start" | "end"`, `side="top" | "bottom"`

**Animated**

- **MessageAnimated** - reads a local message object, extracts text parts, and fades the bubble in on mount

## Hooks

The three hooks must be called inside `<MessageScrollerProvider>`. They return values from the nearest provider context.

### useMessageScroller()

Returns imperative scroll methods:

- `scrollToEnd(opts?)` - scroll the viewport to the bottom; returns `true` if the viewport exists.
- `scrollToStart(opts?)` - scroll to the top.
- `scrollToMessage(messageId, opts?)` - scroll a specific item into view by its `messageId`.

Each method accepts `{ behavior?: ScrollBehavior, align?: ScrollAlign, scrollMargin?: number }`.

### useMessageScrollerScrollable()

Returns `{ start: boolean, end: boolean }` - whether the viewport can scroll further in each direction. Useful to render custom scroll buttons or fade edges.

### useMessageScrollerVisibility()

Returns `{ currentAnchorId: string | null, visibleMessageIds: string[] }`. `currentAnchorId` is the topmost visible item; `visibleMessageIds` lists every item currently inside the viewport.

## Accessibility

- `MessageScrollerButton` renders a native `<button>` with an `sr-only` label (Scroll to end / Scroll to start).
- `MessageScrollerViewport` uses `overscroll-contain` so nested scroll contexts do not chain to the page.
- `MessageScrollerItem` sets `content-visibility: auto` for off-screen performance; screen readers still announce off-screen items when navigating.
- `Bubble` renders a plain `<div>`. Use `BubbleContent` with `as="a"` or `as={Link}` for clickable bubbles; do not nest interactive content inside a non-interactive bubble.

## Best Practices

- **Always wrap the scroller in `MessageScrollerProvider`.** The provider owns the scroll context; children throw if the context is missing.
- **Pass `messageId` on every `MessageScrollerItem`.** Without it, `scrollToMessage` and visibility tracking cannot find the item.
- **Use `MessageAnimated` for streamed replies.** It accepts a local message object and handles text extraction and fade-in.
- **Reduce motion is honored automatically.** When the OS requests reduced motion, transitions are disabled; `motion` values are ignored.
- **Prefer `Bubble` variants over custom colors.** The seven built-in variants cover the common message types.
