Tool renders a tool call as a trace row. The row shows the command, a status glyph, and the output in a code block. Failing calls expand by default. Approvals render as a prompt outside the trace.

Tool is a **composition**, not a primitive. It composes [Trace](/docs/components/trace) and [Code Block](/docs/components/code-block).

    <CodeBlock>
      <CodeBlockContent />
    </CodeBlock>
  </TraceCollapsibleContent>
</TraceCollapsible>
~~~

- **TraceCollapsible** — one per call, header has the command and status
- **TraceLine** — a single row, `status` drives icon and color
- **Code Block** — the tool output (stdout or error text)

## States

A call can be running, done, error, denied, or pending approval. Each maps to a different row.

## Approval

Mark a tool with `needsApproval: true` and the call pauses with `state: "approval-requested"`. Render it as an [Item](/docs/components/item) outside the trace, with Deny and Approve buttons. `addToolApprovalResponse` from `useChat` sends the decision, and `sendAutomaticallyWhen` resumes the assistant turn.

~~~ts title="tool.ts"
writer.tool("runCommand", {
  input: { command: "rm -rf dist" },
  needsApproval: true,
  output: { stdout: "" },
})
~~~

## Accessibility

- The status icon is decorative. The `TraceTitle` carries the state.
- Approval prompts use `Item` with two buttons. Each button is a real `<button>` with a clear label.
- Failed calls auto-expand their output. Screen readers announce the open state via the trigger.
- `prefers-reduced-motion` disables the spinner and collapse animation.

## Best Practices

- **Show the command, not the tool name.** Users care what runs, not what it is called.
- **Auto-expand failures.** A failing tool needs its output visible.
- **Ask before destructive commands.** `needsApproval` for anything that writes or deletes.
- **Pair with a plain-text summary.** The tool row is evidence, not the answer.
