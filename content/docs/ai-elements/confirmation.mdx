Confirmation pauses a tool call and asks the user to approve or deny it before it runs. The pending tool renders as an `Item` card with Approve and Deny actions. Once the user responds, the card is replaced by a `Trace` line showing the outcome.

Confirmation is a composition — install the primitives, then wire the approval flow the same way the demo does.

## Usage

Mark the tool call with `needsApproval: true`. The writer emits an `approval-requested` state instead of running the tool immediately.

```tsx title="chat.tsx"
import { createChat } from "@frakment/ai";
import type { UIDataTypes, UIMessage } from "ai";

type ChatMessage = UIMessage<
  unknown,
  UIDataTypes,
  { runCommand: { input: { command: string }; output: { stdout: string } } }
>;

const chat = createChat<ChatMessage>()
  .user("Clean up the build folder.")
  .assistant(({ writer }) => {
    writer.tool("runCommand", {
      input: { command: "rm -rf dist" },
      needsApproval: true,
      output: { stdout: "" },
    });
  });
```

Wire the approval handler into `useChat` and let the SDK auto-send the follow-up turn.

```tsx title="chat.tsx"
import { useChat } from "@ai-sdk/react";
import { lastAssistantMessageIsCompleteWithApprovalResponses } from "ai";

const { messages, addToolApprovalResponse } = useChat({
  messages: initialMessages,
  transport,
  sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithApprovalResponses,
});
```

## Anatomy

A pending tool call renders as an `Item` card. Once approved or denied, it becomes a `Trace` line.

```tsx title="confirmation.tsx"
{part.state === "approval-requested" ? (
  <Item variant="outline" size="sm">
    <ItemMedia variant="icon">
      <TerminalIcon />
    </ItemMedia>
    <ItemContent>
      <ItemTitle>Run {part.input.command}?</ItemTitle>
      <ItemDescription>The command runs in this project.</ItemDescription>
    </ItemContent>
    <ItemActions>
      <Button
        size="sm"
        variant="outline"
        onClick={() =>
          addToolApprovalResponse({ id: part.approval.id, approved: false })
        }
      >
        Deny
      </Button>
      <Button
        size="sm"
        onClick={() =>
          addToolApprovalResponse({ id: part.approval.id, approved: true })
        }
      >
        Approve
      </Button>
    </ItemActions>
  </Item>
) : (
  <Trace>
    <TraceLine status={!denied && part.state !== "output-available" ? "running" : undefined}>
      <TraceIcon><TerminalIcon /></TraceIcon>
      <TraceTitle>
        {denied ? "Denied" : part.state === "output-available" ? "Ran" : "Running"}{" "}
        {part.input?.command}
      </TraceTitle>
    </TraceLine>
  </Trace>
)}
```

- **Item** — the pending approval card with media, content, and actions.
- **Button** — Approve (default) and Deny (outline).
- **Trace** — the outcome row, shown after the user responds.
- **Message**, **Bubble** — surrounding turn.

## Approval states

The tool call moves through states:

| State | Render |
| :-- | :-- |
| `input-streaming` | hidden (input not yet available) |
| `approval-requested` | `Item` card with Approve / Deny |
| `approval-responded` | `Trace` line, running if approved |
| `output-available` | `Trace` line showing "Ran [command]" |
| `output-denied` | `Trace` line showing "Denied [command]" |

## Animation

User turns animate with the `slide-up` variant, assistant turns fade in, and the approval card slides up when it appears.

```tsx title="confirmation.tsx"
import { MESSAGE_ANIMATIONS } from "@/lib/message-animations";
import { motion, useReducedMotion } from "motion/react";

const shouldReduceMotion = useReducedMotion();

<motion.div
  animate={shouldReduceMotion ? undefined : "animate"}
  initial={shouldReduceMotion ? undefined : "initial"}
  variants={MESSAGE_ANIMATIONS["slide-up"].variants}
>
  <Item variant="outline" size="sm">...</Item>
</motion.div>
```

Motion is skipped when the user prefers reduced motion.

## Accessibility

- The approval card is an `Item` with `role="group"`. Both buttons are focusable and labelled ("Approve", "Deny").
- `addToolApprovalResponse` resolves on click and keyboard. The card unmounts and focus returns to the transcript.
- The pending state is announced with `aria-live="polite"`. Do not use `assertive`.
- The resulting Trace line reports "Ran command" or "Denied command".

## Best Practices

- **Ask only when needed.** Set `needsApproval: true` for destructive or outbound actions.
- **Show the exact command.** The user needs to see what will run.
- **Use clear verbs.** "Approve" and "Deny" beat "Yes" and "No".
- **Resolve the tool immediately after approval.** Emit `output-available` or `output-denied`.
- **Do not double-prompt.** Once responded, hide the card and stream the outcome.
