Message Pattern shows a user turn and an assistant turn with the pieces that make a real conversation feel finished: markdown content, a copy action, feedback buttons, and a retry action. It composes Message, Bubble, Tooltip, Button, and Markdown.

Message is a **composition**, not a primitive. Install the five primitives it uses, then wire it the same way the demo does.

## Anatomy

```tsx title="message-demo.tsx"
<Message align="end">
  <MessageContent>
    <Bubble align="end" variant="muted">
      <BubbleContent>{userText}</BubbleContent>
    </Bubble>
    <MessageFooter>
      <MessageAction label="Copy"><CopyIcon /></MessageAction>
      <MessageAction label="Edit"><PencilIcon /></MessageAction>
    </MessageFooter>
  </MessageContent>
</Message>

<Message>
  <MessageContent>
    <Markdown>{reply}</Markdown>
    <MessageFooter>
      <MessageAction label="Copy"><CopyIcon /></MessageAction>
      <MessageAction label="Good response"><ThumbsUpIcon /></MessageAction>
      <MessageAction label="Bad response"><ThumbsDownIcon /></MessageAction>
      <MessageAction label="Retry"><RefreshCcwIcon /></MessageAction>
    </MessageFooter>
  </MessageContent>
</Message>
```

- **Message** — the row, with `align` for user (`end`) or assistant (`start`).
- **MessageContent** — vertical stack for bubble + footer.
- **Bubble**, **BubbleContent** — the surface for the user message.
- **Markdown** — renders the assistant reply, including fenced code blocks.
- **MessageFooter** — horizontal action row aligned to the message.
- **MessageAction** — a Button wrapped in a Tooltip, with `aria-label` for the icon.

## Copy feedback

The copy action swaps to a checkmark for two seconds after clicking. Wire it with a single state:

```tsx
const [copied, setCopied] = React.useState(false);
React.useEffect(() => {
  if (!copied) return;
  const t = setTimeout(() => setCopied(false), 2000);
  return () => clearTimeout(t);
}, [copied]);
```

## Feedback toggle

Like and dislike are independent toggles. Track a single `feedback` state and use `aria-pressed` so screen readers announce the state:

```tsx
<MessageAction
  aria-pressed={feedback === "like"}
  label="Good response"
  onClick={() => setFeedback(feedback === "like" ? null : "like")}
>
  <ThumbsUpIcon className={feedback === "like" ? "fill-current" : undefined} />
</MessageAction>
```

## Best Practices

- **Only show actions after the response finishes streaming.** A copy button on a partially-streamed reply copies incomplete text.
- **Use real buttons, not styled text.** `MessageAction` renders a `Button` inside a `Tooltip` — keep that structure so keyboard users can reach it.
- **Icon-only actions need a label.** Pass `aria-label` and put the same string in the tooltip.
- **Keep the footer aligned with the message.** Do not use `justify-between` to spread the actions; they cluster.
- **Do not nest interactive content inside Bubble.** Actions belong in `MessageFooter`.

## Accessibility

- Each `MessageAction` is a real `<button>` with `aria-label` matching its tooltip.
- Feedback toggles use `aria-pressed` so screen readers announce "pressed" or "not pressed".
- The copy state is announced via the tooltip and the swapped icon; the button keeps its accessible name throughout.
- Code blocks render inside `Markdown` and preserve syntax highlighting for screen readers.
