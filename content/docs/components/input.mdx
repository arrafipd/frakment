Input is a single-line text field for forms and inline editing. It inherits all native `<input>` attributes and behaviors, and pairs with [Field](/docs/components/field) for labels and descriptions.

Set `aria-invalid` on the input, or `data-invalid` on the **Field** wrapper, to trigger destructive styling.

```tsx
</Field>
```

## Accessibility

- `Input` renders a native `<input>`. It has no label by default; always pair with a `Label` or `FieldLabel`.
- Use the native `type` attribute (`email`, `url`, `tel`, `number`) so mobile keyboards adapt.
- Set `aria-invalid` and `aria-describedby` on error. Do not rely on a red border alone.
- `disabled` removes the input from the tab order. For informational values, use `readOnly`.

## Best Practices

- **Always label the input.** Placeholders disappear after typing; labels stay.
- **Use the native type.** `email`, `url`, `tel`, and `number` trigger the right keyboard on mobile.
- **Show errors inline.** Use `aria-invalid` and a description below the input, not a toast.
- **Do not disable without reason.** Disabled inputs are invisible to screen readers.
- **Cap length with `maxLength`.** Do not rely on server-side validation alone.
