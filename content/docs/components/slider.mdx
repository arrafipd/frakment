
## Anatomy

```tsx title="slider.tsx"
<Slider>
  <SliderTrack>
    <SliderRange />
  </SliderTrack>
  <SliderThumb />
</Slider>
```

- **Root** — flex container, horizontal or vertical
- **Track** — muted background rail
- **Range** — filled portion between min and current value
- **Thumb** — draggable handle, one per value

### Slider

Extends Radix `Slider.Root`.

### SliderTrack

Extends Radix `Slider.Track`. Muted rail behind the fill. Height `1` horizontal, width `1` vertical.

### SliderRange

Extends Radix `Slider.Range`. Filled portion between `min` and the current value.

### SliderThumb

Extends Radix `Slider.Thumb`. One per value. Focusable with arrow keys, Home, and End.

## Controlled


| Key | Action |
| :-- | :-- |
| `←` / `→` | Decrease / increase value |
| `↑` / `↓` | Decrease / increase value |
| `Home` / `End` | Min / max |
| `Page Up` / `Page Down` | Step up / down |

## Accessibility

## Accessibility

- Radix Slider exposes `role="slider"` with `aria-valuemin`, `aria-valuemax`, and `aria-valuenow` per thumb.
- Each thumb is keyboard focusable and responds to arrow keys, Home, and End.
- Pair the slider with a `Label` when the slider is not self-describing.

## Best Practices

- **Use `onValueChange` for live preview, `onValueCommit` for persistence.** Live updates keep the UI responsive; commit on release avoids a flood of writes.
- **Show the current value.** A slider without a visible number or label is hard to read. Pair it with `ProgressValue` or a custom span.
- **Prefer ranges when both ends matter.** Use two thumbs for temperature, price, or scale intervals.
- **Add a label.** Link a `Label` with `htmlFor` to the slider `id` so screen readers announce it.
- **Do not replace a numeric input.** Sliders are imprecise for exact values. Pair with a number input when precision matters.
