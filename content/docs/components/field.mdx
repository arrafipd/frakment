Field wraps a form control with its label, description, and error message. It handles vertical and horizontal orientation, works with `FieldSet` and `FieldGroup` for multi-field forms, and surfaces validation state through `data-invalid` on the wrapper.

## Usage

```tsx title="field.tsx"
import { Field, FieldDescription, FieldLabel } from "@/components/ui/field";
import { Input } from "@/components/ui/input";
```

```tsx
<Field>
  <FieldLabel htmlFor="email">Email</FieldLabel>
  <Input id="email" type="email" placeholder="name@example.com" />
  <FieldDescription>We'll send updates to this address.</FieldDescription>
</Field>
```

## Anatomy

```tsx
<FieldSet>
  <FieldLegend>Section title</FieldLegend>
  <FieldDescription>Section description</FieldDescription>
  <FieldGroup>
    <Field>
      <FieldLabel />
      <Input />
      <FieldDescription />
    </Field>
  </FieldGroup>
</FieldSet>
```

- **FieldSet** — semantic `<fieldset>` wrapper for grouped fields
- **FieldLegend** — `<legend>` for the set
- **FieldGroup** — vertical flex column with consistent gap
- **Field** — wraps one control + label + description; `orientation` switches between vertical (default) and horizontal
- **FieldContent** — stack for label + description when placed beside the control (horizontal mode)
- **FieldLabel** — the label; when used with a checkbox or switch, allows click-through to toggle
- **FieldTitle** — bold title, used inside **FieldContent** when the description is below
- **FieldDescription** — muted helper text below (or beside, in horizontal mode) the control
- **FieldError** — inline error message; accepts `children` or an `errors` array
- **FieldSeparator** — visual break between fields or sets, with optional inline label

### Invalid

Set `data-invalid` on **Field** (or `aria-invalid` on the control) to trigger destructive styling on the label and control ring.

<ComponentPreview name="field" title="field.tsx" previewClassName="h-auto py-8">
  <FieldInvalid />
</ComponentPreview>

```tsx
<Field data-invalid>
  <FieldLabel htmlFor="email">Email</FieldLabel>
  <Input id="email" aria-invalid />
  <FieldDescription>This field contains validation errors.</FieldDescription>
</Field>
```

### With FieldError

```tsx
<Field data-invalid>
  <FieldLabel htmlFor="email">Email</FieldLabel>
  <Input id="email" aria-invalid />
  <FieldError>Email is required.</FieldError>
</Field>
```

### Horizontal with FieldContent

`orientation="horizontal"` places the label and control side by side. Use **FieldContent** to stack a title and description beside the control.

```tsx
<Field orientation="horizontal">
  <Checkbox id="terms" />
  <FieldLabel htmlFor="terms">Accept terms and conditions</FieldLabel>
</Field>
```

```tsx
<Field orientation="horizontal">
  <FieldContent>
    <FieldTitle>Share across devices</FieldTitle>
    <FieldDescription>Focused settings sync between devices.</FieldDescription>
  </FieldContent>
  <Switch id="sync" />
</Field>
```

## Accessibility

- `Field` does not add roles. It is a layout primitive that groups `FieldLabel` with its control.
- Use `htmlFor` on `FieldLabel` and `id` on the control.
- `FieldError` is linked automatically when the parent `Field` has `data-invalid`.

## Best Practices

- **One Field per control.** Do not nest fields.
- **Use `FieldGroup` for multiple fields.** It normalizes vertical spacing.
- **Horizontal orientation works for Checkbox and Switch.** Not for inputs.
- **Pair label with description, not placeholder.** Placeholders disappear.
