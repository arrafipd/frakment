Attachment renders a compact file card with media, title, description, and actions. It supports upload states, size variants, image thumbnails, and an overlay trigger that makes the entire card interactive.

## Anatomy

```tsx title="attachment.tsx"
<Attachment>
  <AttachmentMedia />
  <AttachmentContent>
    <AttachmentTitle />
    <AttachmentDescription />
  </AttachmentContent>
  <AttachmentActions>
    <AttachmentAction />
  </AttachmentActions>
  <AttachmentTrigger />
</Attachment>
```

- **Attachment** — flex row, 3px radius, accepts `state`, `size`, and `orientation`
- **AttachmentMedia** — 16px icon slot; pass `variant="image"` to render a 40px thumbnail
- **AttachmentContent** — vertical stack for title and description
- **AttachmentTitle** — truncated file name, medium weight
- **AttachmentDescription** — small muted metadata line
- **AttachmentActions** — cluster of actions aligned to the end
- **AttachmentAction** — 24px ghost button, requires `aria-label`
- **AttachmentTrigger** — absolute overlay that fills the card; accepts `asChild`

## Images

Pass `variant="image"` to **AttachmentMedia** to render a thumbnail instead of an icon. Combine with `orientation="vertical"` for a taller card.

## Group

Wrap multiple attachments in **AttachmentGroup** to enable horizontal snap scrolling. Cards keep their intrinsic width and snap into place on touch devices.

## Trigger

Wrap the card with **AttachmentTrigger** and use `asChild` to render a link or a dialog trigger behind the actions. The trigger fills the card so the entire surface is clickable while actions stay independently interactive.

<ComponentPreview name="attachment" title="attachment.tsx">
  <AttachmentTriggerDemo />
</ComponentPreview>

```tsx title="attachment.tsx"
<Attachment>
  <AttachmentMedia>
    <FileSearchIcon />
  </AttachmentMedia>
  <AttachmentContent>
    <AttachmentTitle>research-summary.pdf</AttachmentTitle>
    <AttachmentDescription>Open preview dialog</AttachmentDescription>
  </AttachmentContent>
  <AttachmentActions>
    <AttachmentAction aria-label="Remove">
      <XIcon />
    </AttachmentAction>
  </AttachmentActions>
  <DialogTrigger asChild>
    <AttachmentTrigger aria-label="Preview research-summary.pdf" />
  </DialogTrigger>
</Attachment>
```

## Accessibility

- **AttachmentTrigger** is an absolute overlay. Give it an `aria-label` describing the target action, such as "Preview report.pdf".
- **AttachmentAction** buttons are icon-only. Every action must have an `aria-label` so screen readers can announce its intent.
- Do not attach click handlers to the card itself. Use **AttachmentTrigger** with `asChild` so the click target is a real anchor or button.
- Pair color with icon or text. The error state uses `file-warning` and a description — never rely on color alone.
- When `state="uploading"`, render **Spinner** inside **AttachmentMedia** and include the progress in **AttachmentDescription** so the state is announced.

## Best Practices

- **Use `state` for lifecycle, not decoration.** Every state maps to a real upload phase — idle, uploading, processing, error, done.
- **Keep file names visible.** **AttachmentTitle** truncates with ellipsis; do not replace it with an icon-only card.
- **Use `orientation="vertical"` for image attachments.** Horizontal orientation reserves less vertical space but hides the image.
- **Prefer `AttachmentGroup` for lists.** It normalizes spacing and snap behavior between cards.
- **Wrap with `asChild` for links.** A plain overlay without `asChild` is a button with no semantic role; wrap it in `<a>` or `<DialogTrigger>`.
