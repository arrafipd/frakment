Frakment uses **CSS variables** for theming. Every component references semantic tokens like `bg-background`, `text-foreground`, `border-border` — never hardcoded colors. Change the tokens, change the entire look of your app.

Theme tokens live directly in your `globals.css`, wrapped between `/* ==== FRAKMENT THEME START ==== */` and `/* ==== FRAKMENT THEME END ==== */`. `npx frakment init` injects the block automatically. Manual setup is one copy-paste.

## Where the tokens live

Frakment injects its theme tokens directly into `globals.css`, wrapped between two markers. `npx frakment init` sets up:

- **Theme block in `globals.css`** — tokens, dark mode, component utilities
- **`components.json`** — CLI config (registry URL, aliases, globals.css path)

The block goes **after** all your `@import` statements. Placement looks like this:

```css title="app/globals.css"
@import "tailwindcss";
/* ==== FRAKMENT THEME START ==== */
```

The block is self-contained: it defines `@theme inline`, `:root` (light), `.dark` (dark), `@custom-variant dark`, and 9 `@utility` helpers. To customize the look, edit the block in `globals.css` — anywhere between the markers.

**Tailwind v4 required.** The theme block uses `@theme`, `@utility`, and `@custom-variant` — Tailwind v3 is not supported.

## Token convention

Each surface token has a matching `-foreground` token for text on that surface. Components use both, so you only change two values per surface.

- `primary` → `primary-foreground`
- `secondary` → `secondary-foreground`
- `muted` → `muted-foreground`
- `card` → `card-foreground`
- `popover` → `popover-foreground`
- `accent` → `accent-foreground`
- `destructive` — no `-foreground`; always uses white text

Each surface token controls a background; its paired `-foreground` controls text on that surface. This keeps contrast automatic and makes light/dark mode trivial.

## Theme tokens

Define these in `:root` (light) and `.dark` (dark mode) inside the FRAKMENT THEME block:

| Token                                | Controls                       | Used by                              |
| :----------------------------------- | :----------------------------- | :----------------------------------- |
| `background` / `foreground`          | Page background and text       | Page shell, sections                 |
| `card` / `card-foreground`           | Elevated surfaces              | Card, panels                         |
| `popover` / `popover-foreground`     | Floating surfaces              | Popover, DropdownMenu                |
| `primary` / `primary-foreground`     | High-emphasis actions          | Default Button, selected states      |
| `secondary` / `secondary-foreground` | Lower-emphasis actions         | Secondary buttons                    |
| `muted` / `muted-foreground`         | Subtle surfaces                | Descriptions, placeholders           |
| `accent` / `accent-foreground`       | Hover and focus surfaces       | Ghost buttons, hover rows            |
| `destructive`                        | Errors and destructive actions | Destructive buttons, error states    |
| `border`                             | Borders and separators         | Cards, Separator, inputs             |
| `input`                              | Form control borders           | Input, Textarea                      |
| `ring`                               | Focus rings                    | Buttons, inputs                      |
| `radius`                             | Base corner radius             | All rounded elements                 |
| `surface` / `surface-foreground`     | Docs surface tokens            | Callout, LinkedCard                  |
| `code` / `code-foreground`           | Code block background and text | Code Block, inline code              |
| `sidebar-*`                          | Sidebar tokens                 | Sidebar, docs navigation             |
| `chart-*`                            | Data visualization colors      | Reserved for future chart components |

## Radius scale

`--radius` is the base. Smaller and larger radii are derived from it by the components:

```css title="globals.css"
:root {
  --radius: 0.625rem;
  /* Components reference: */
  /* radius-sm = calc(var(--radius) - 4px) */
  /* radius-md = calc(var(--radius) - 2px) */
  /* radius-lg = var(--radius) */
  /* radius-xl = calc(var(--radius) + 4px) */
}
```

Change `--radius` once and the entire radius scale updates across all components.

## Adding a new token

Define it under `:root` and `.dark`, then expose it with `@theme inline`:

```css title="app/globals.css"
:root {
  --warning: oklch(0.84 0.16 84);
  --warning-foreground: oklch(0.28 0.07 46);
}

.dark {
  --warning: oklch(0.41 0.11 46);
  --warning-foreground: oklch(0.99 0.02 95);
}

@theme inline {
  --color-warning: var(--warning);
  --color-warning-foreground: var(--warning-foreground);
}
```

Now you can use `bg-warning` and `text-warning-foreground` in your components.

## Base colors

Frakment works with any OKLCH palette. These base colors all work with the default theme without changes:

| Base    | Character          |
| :------ | :----------------- |
| Neutral | Pure gray          |
| Stone   | Warm gray          |
| Zinc    | Cool gray          |
| Mauve   | Purple-tinted gray |
| Olive   | Green-tinted gray  |
| Mist    | Blue-tinted gray   |
| Taupe   | Brown-tinted gray  |

Swap the OKLCH values in `:root` and `.dark` for any of these — Frakment components don't care which base you choose, they only read tokens.

## Dark mode

Frakment's dark mode is wired through two pieces in the theme block:

1. **`@custom-variant dark (&:is(.dark *))`** — registers the `dark:` Tailwind variant
2. **A `.dark { ... }` block** — dark token values

When `<html class="dark">`, every `dark:*` utility and every token in `.dark` kicks in. When `.dark` is absent, `:root` tokens apply.

```css title="app/globals.css"
@custom-variant dark (&:is(.dark *));

:root {
  --background: oklch(1 0 0);
  --foreground: oklch(0.145 0 0);
}

.dark {
  --background: oklch(0.145 0 0);
  --foreground: oklch(0.985 0 0);
}
```

### Toggle dark mode

Any method that toggles `.dark` on `<html>` works. The docs site uses [`next-themes`](https://github.com/pacocoursey/next-themes):

<CodeCollapsibleWrapper>

```tsx title="components/theme-provider.tsx"
"use client";

import { ThemeProvider as NextThemesProvider } from "next-themes";

export function ThemeProvider({
  children,
  ...props
}: React.ComponentProps<typeof NextThemesProvider>) {
  return <NextThemesProvider {...props}>{children}</NextThemesProvider>;
}
```

```tsx title="app/layout.tsx"
import { ThemeProvider } from "@/components/theme-provider";

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body>
        <ThemeProvider
          attribute="class"
          defaultTheme="system"
          enableSystem
          disableTransitionOnChange
        >
          {children}
        </ThemeProvider>
      </body>
    </html>
  );
}
```

</CodeCollapsibleWrapper>

`suppressHydrationWarning` is required because `next-themes` sets `.dark` on the client after hydration. Without it, React warns about a server/client mismatch.

### Manual toggle (no library)

If you don't want a library, toggle the class yourself:

```tsx
"use client";

export function ThemeToggle() {
  return (
    <button onClick={() => document.documentElement.classList.toggle("dark")}>
      Toggle theme
    </button>
  );
}
```

To persist the choice, store it in `localStorage` and apply on mount. Or use [`next-themes`](https://github.com/pacocoursey/next-themes) (recommended).

### Using `dark:` utilities

Because `@custom-variant dark` is registered in the theme block, all `dark:` utilities work out of the box:

```tsx
<div className="bg-background text-foreground dark:bg-card dark:text-card-foreground" />
```

You don't need to configure Tailwind's `darkMode` option — Frakment uses a custom variant instead of the built-in `class` strategy.

### Per-section theming (advanced)

If you want a section of your app to always render in one mode, apply `.dark` to a wrapper:

```tsx
<div className="dark">
  <Card>Always dark, regardless of root theme.</Card>
</div>
```

This works because the variant matches `.dark *` (any descendant of `.dark`), not just `<html>`.

## FAQ

<Accordion type="single" collapsible>

<AccordionItem value="why-oklch">
<AccordionTrigger>Why OKLCH instead of hex or HSL?</AccordionTrigger>
<AccordionContent>

OKLCH is a perceptual color space — colors with the same lightness value look equally bright. This makes theme tokens consistent across hues and lets dark mode swap lightness without changing hue.

</AccordionContent>
</AccordionItem>

<AccordionItem value="custom-base">
<AccordionTrigger>Can I use my own brand color?</AccordionTrigger>
<AccordionContent>

Yes. Set `--primary` and `--primary-foreground` to your brand colors. Keep the contrast ratio at WCAG AA (4.5:1 minimum) and everything else stays consistent.

</AccordionContent>
</AccordionItem>

<AccordionItem value="css-vars-off">
<AccordionTrigger>Can I disable CSS variables?</AccordionTrigger>
<AccordionContent>

Not out of the box. Frakment components reference semantic tokens (`bg-background`, `text-foreground`). You would need to rewrite each component to use inline utilities instead — not recommended.

</AccordionContent>
</AccordionItem>

</Accordion>
