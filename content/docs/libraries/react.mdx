`@frakment/react` is the headless engine that powers `<MessageScroller>`. It replaces the temporary external dependency currently used in `components/ui/message-scroller.tsx`.

<Callout type="warning" title="In development">
  The Frakment React engine is not published yet. This page tracks the target
  API, behaviour contracts, and migration plan. Code samples reflect the planned
  design, not the current implementation.
</Callout>

## Behaviour contract

- **Auto-scroll on content change** — viewport pins to bottom only while `atBottom` is `true`
- **Pause on user scroll-up** — a user scroll away from the bottom pauses auto-scroll
- **Re-engage on return** — scrolling back to the bottom resumes auto-scroll
- **Turn anchoring** — `MessageScrollerItem scrollAnchor` settles the turn near the top of the viewport with a peek of the previous turn
- **Streaming-safe** — new content arriving mid-stream never fights a user who scrolled up
- **ARIA** — `role="log"` + `aria-relevant="additions"` so screen readers announce new messages
- **Empty state** — zero messages renders without crashing (`scrollable = false`)

## Migration

Until the port lands, `components/ui/message-scroller.tsx` depends on an external headless engine. When `@frakment/react` is published:

<Steps className="mb-0 pt-2">
  <Step>Install the new package: `npm install @frakment/react`.</Step>
  <Step>Replace the import in `components/ui/message-scroller.tsx`.</Step>
  <Step>Update the `dependencies` field in the corresponding `frakment.json` registry entry.</Step>
  <Step>Run `npm run registry:build` to regenerate `public/r/message-scroller.json`.</Step>
  <Step>Verify behaviour against the current demos: `message-scroller-demo.tsx`, plus any `<MessageScroller>` usage in docs.</Step>
</Steps>

### Import change

```diff title="components/ui/message-scroller.tsx"
- import { MessageScroller as MessageScrollerPrimitive } from "external-engine";
+ import { MessageScroller as MessageScrollerPrimitive } from "@frakment/react";
```

### Registry entry change

```diff title="frakment.json"
  {
    "name": "message-scroller",
-   "dependencies": ["@phosphor-icons/react", "external-engine"],
+   "dependencies": ["@phosphor-icons/react", "@frakment/react"],
    "registryDependencies": ["button", "icons"]
  }
```

<Callout type="info" title="No API change for consumers">
  Application code does not change. The migration is limited to the import path
  and dependency name inside the Frakment source. Every `data-*` attribute,
  prop, and hook signature stays identical.
</Callout>

## Design principles

- **Headless.** Zero styling. All visuals come from `className` passed by the consumer.
- **Deterministic.** No timers outside of `requestAnimationFrame`. Every render is a function of scroll position + content height.
- **Hooks-first.** Core logic lives in hooks so it can be reused with React Server Components where possible.
- **Parity-first.** Every behaviour, `data-*` attribute, and ARIA role matches the reference implementation 1:1.
