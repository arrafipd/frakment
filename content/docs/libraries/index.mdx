Frakment ships three runtime layers beyond the component registry. Each is source-available, fully in-repo, and independently installable.

## Layers

| Layer            | Import                    | Purpose                                  | Status                 |
| ---------------- | ------------------------- | ---------------------------------------- | ---------------------- |
| **frakment CLI** | `npx frakment@latest ...` | Install components + theme               | Stable                 |
| **AI helpers**   | `@/lib/ai`                | Deterministic chat engine (`createChat`) | Stable (repo-internal) |
| **React engine** | `@frakment/react`         | Headless message-scroller engine         | Planned                |

## Design principles

- **Zero external engine dependencies.** Every runtime layer is source-available and fully in-repo.
- **Deterministic.** No network calls, no model invocations. Same input → same output.
- **Composable.** CLI, AI helper, and React engine are independently installable.
- **Contract-first.** When replacing an existing library, the public API and behaviour match the contract consumers already rely on — no surprises.

## Distribution

| Layer                            | Installed via                    |
| -------------------------------- | -------------------------------- |
| Components (`button`, `card`, …) | `npx frakment@latest add <name>` |
| Theme (tokens + utilities)       | `npx frakment@latest init`       |
| AI helpers (`@/lib/ai`)          | Bundled with this repo           |
| React engine                     | Future npm package               |

<Callout type="info" title="AI helpers are repo-internal">
  `@/lib/ai` currently ships with the Frakment source. When you copy components
  that depend on it (such as `message-scroller` demos), also copy `lib/ai/`.
  Publishing as `@frakment/ai` is planned.
</Callout>
