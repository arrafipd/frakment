`@/lib/ai` is Frakment's deterministic chat engine — a `createChat()` builder that scripts transcripts, streams them as AI SDK v7 `UIMessageChunk`s, and lets you test chat UIs without calling a model.

## Installation

<Callout type="info" title="Included with dependent components">
  The engine ships as a registry item (`ai`). Install any component that depends on it
  (`message-animated`) and `lib/ai/` lands in your project automatically.
</Callout>

## Quick start

```tsx title="chat.ts"
import { createChat, getMessageText } from "@/lib/ai";

const chat = createChat()
  .user("Hello")
  .sleep(500)
  .assistant("Hi! How can I help?")
  .user("What's the weather?")
  .assistant("It's sunny and 72°F.");

const initialMessages = chat.get(0); // UIMessage[]
const transport = chat.transport({ delayMs: 20 });
const nextMessage = chat.next(messages); // UIMessage | null
```

Wire it to `useChat` from `@ai-sdk/react`:

```tsx
import { useChat } from "@ai-sdk/react";

const { messages, sendMessage, status } = useChat({
  messages: initialMessages,
  transport,
});
```

## Assistant callback DSL

Pass a callback to `.assistant()` for full control over parts and timing. The callback receives a `writer` — a fluent DSL that appends events to the turn.

```tsx
chat.assistant(({ writer }) => {
  writer
    .reasoning("Let me think...")
    .sleep(300)
    .text("Here's the answer:")
    .text("42", { mode: "instant" });
});
```

## Tools

```tsx
chat.assistant(({ writer }) => {
  writer
    .text("Searching...")
    .tool("web_search", {
      input: { query: "Next.js 16 release notes" },
      output: { results: [...] },
      title: "Web search",
    })
    .text("Found the answer.")
})
```

`writer.tool()` returns a `ToolHandle` for streaming multi-step tools:

```tsx
const handle = writer.tool("long_task", { input: { jobId: 123 } });
handle
  .sleep(500)
  .output({ progress: 30 }, { preliminary: true })
  .sleep(500)
  .output({ result: "done" }); // final output
```

## Human-in-the-loop approvals

Set `needsApproval: true` to pause the turn. The follow-up `.assistant(callback)` becomes a **continuation turn** — it materializes only when a real transcript arrives, and receives `{ toolCall, toolCalls, messages }` in its context.

```tsx
chat
  .user("Send an email to the team.")
  .assistant(({ writer }) => {
    writer.text("I'll send it, but I need your approval first.");
    writer.tool("send_email", {
      input: { to: "team@company.com", subject: "Update" },
      needsApproval: true,
    });
  })
  .assistant(({ writer, toolCall }) => {
    if (toolCall?.approved) {
      writer.text("Email sent.");
    } else {
      writer.text("Email was not sent.");
    }
  });
```

<Callout type="info" title="Continuation turns">
  A continuation turn has no materialized message until a live transcript
  arrives. `chat.get(count)` stops before the first continuation turn, and
  `chat.next(messages)` matches by message ID (fallback: role + text).
</Callout>

## Helper functions

### `getMessageText(message)`

Extracts the concatenated text parts from a `UIMessage`. Returns `""` if no text parts exist.

```ts
import { getMessageText } from "@/lib/ai";

const text = getMessageText(messages[0]);
```

### `getToolCalls(message)`

Extracts tool call descriptors from a `UIMessage`. Each descriptor: `{ toolCallId, name, dynamic, input, output, errorText, state, approval? }`.

## Architecture

`lib/ai/` is split into focused modules:

| File          | Purpose                                                                                  |
| ------------- | ---------------------------------------------------------------------------------------- |
| `types.ts`    | Public + internal TypeScript interfaces                                                  |
| `ids.ts`      | ID generator with reserve/next semantics                                                 |
| `utils.ts`    | `assertNever`, `abortableSleep`, `deepClone`, `splitWords`, `stripDataPrefix`, `devWarn` |
| `payloads.ts` | File / reasoning / source / custom payload factory                                       |
| `envelope.ts` | `materializeParts`, `eventsFromParts`, `eventsToEnvelope`                                |
| `stream.ts`   | `streamFromEnvelope` — `ReadableStream<UIMessageChunk>`                                  |
| `writer.ts`   | `EventWriter` + `ToolHandle` DSL                                                         |
| `builder.ts`  | `ChatBuilder` — core methods, continuation, transport                                    |
| `adapter.ts`  | `getMessageText`, `getToolCalls`, `FrameworkAdapter`                                     |
| `index.ts`    | Barrel export + `createChat` factory                                                     |

## Behavior

`@/lib/ai` is a first-party chat engine, written from scratch to match the API contract that chat builders rely on. Every `data-*` attribute, ARIA role, timing constant, chunk encoding, and continuation semantic follows the same shape — swapping between `@/lib/ai` and other chat engines requires no consumer code changes.
